💡 The Extension Model

Agents = autonomous workers  |  Skills & Commands = reusable prompts  |  Hooks = event-driven automation

Agents

Specialized AI workers that run in their own isolated context

What Are They?

Think of agents as specialized coworkers you delegate tasks to. Each agent gets its own conversation, tools, and instructions — so their work doesn't clutter yours.

Why Use Them?

  • Isolation — Heavy research stays out of your context
  • Safety — Restrict which tools an agent can use
  • Speed — Run multiple agents in parallel
  • Cost — Route simple tasks to faster/cheaper models

Example: Code Reviewer Agent

--- name: code-reviewer description: Reviews code for security and best practices tools: - Read - Grep - Glob model: sonnet --- You are a code review specialist. Focus on security and maintainability.
📁 Where they live

.claude/agents/*.md (project) or ~/.claude/agents/*.md (global)

Skills & Commands

Shortcuts to predefined prompts — think of them as saved recipes

Skills = Saved Prompts

A skill is a predefined prompt that Claude loads when relevant. Instead of typing the same complex instructions every time, you write them once in a SKILL.md file.

Two ways to trigger:

  • Automatic — Claude detects the skill is relevant from your request and loads it on its own
  • Manual — You type a slash command in the CLI
💡 Commands = CLI-invokable Skills

When you type /deploy or /train in the terminal, you're invoking a skill as a command. Same thing, different entry point.

Example

--- name: deploy description: Deploy the app to production argument-hint: [environment] --- # Deploy Pipeline Deploy to $ARGUMENTS environment. ## Current branch !`git branch --show-current` ## Steps 1. Run tests 2. Build artifacts 3. Deploy to $0

Invoke it:

/deploy production
📁 Where they live

.claude/skills/my-skill/SKILL.md (project) or ~/.claude/skills/ (global)

Hooks

Automatic actions that trigger on specific events — like GitHub Actions, but for Claude

What Are They?

Hooks are shell commands that run automatically when Claude does something specific. They let you add guardrails, validations, or side-effects without changing your prompts.

Available Events

  • PreToolUse — Before Claude runs a tool (block or modify)
  • PostToolUse — After a tool runs (validate results)
  • Stop — When Claude finishes a response
  • SessionStart — When a session begins
  • UserPromptSubmit — When you send a message

Example: Lint After Every Edit

{ "hooks": { "PostToolUse": [{ "matcher": "Edit", "command": "eslint --fix $FILE" }] } }

Example: Block Dangerous Commands

{ "hooks": { "PreToolUse": [{ "matcher": "Bash", "command": "! echo $CMD | grep -q 'rm -rf'" }] } }
📁 Where they live

.claude/settings.json (project) or ~/.claude/settings.json (global)

Skill & Agent Evaluation

Measure, test, and improve your skills and agents systematically

Why Evaluate?

Without evaluation, you're flying blind. Skills may silently regress when prompts change, models update, or new edge cases appear.

What to Evaluate

  • Routing Accuracy — Does the right skill/agent get triggered?
  • Output Quality — Are results correct, complete, and well-formed?
  • Tool Usage — Are the right tools called in the right order?
  • Error Handling — Does it recover gracefully from failures?
  • Guardrails — Are dangerous or off-topic requests blocked?
💡 Golden Rule

Write evals before writing the skill. Define what "good" looks like first, then build toward it.

Evaluation Structure

{ "skill": "train", "tests": [ { "input": "Train a classifier on iris.csv", "assertions": [ "calls preprocess before training", "splits data before any fitting", "reports accuracy on held-out set", "does NOT leak test into train" ] }, { "input": "Train on empty.csv", "assertions": [ "returns clear error message", "does NOT produce a model file" ] } ] }

Key Metrics

Assertion Pass Rate

% of assertions that hold across all test cases

Routing Precision

% of inputs routed to the correct agent/skill

Building Better Skills & Agents

Best practices and the skill-builder plugin for rapid development

Best Practices

🎯

1. Single Responsibility

Each skill does one thing well. Compose multiple skills rather than building monoliths. Small skills are easier to test and reuse.

📋

2. Explicit Trigger Rules

Write clear TRIGGER when and DO NOT TRIGGER when rules. Ambiguous triggers cause routing errors.

🔍

3. Self-Check Loops

Have agents validate their own output before returning. Catch mistakes early with built-in quality gates.

🔧

4. Minimal Tool Surface

Only grant the tools an agent actually needs. Fewer tools = fewer ways to go wrong + faster execution.

The Skill-Builder Plugin

A meta-skill that helps you create, test, and iterate on new skills and agents.

# Scaffold a new skill with tests /skill-builder create --name my-skill --type skill # Generate eval suite from examples /skill-builder eval --skill my-skill --examples 10 # Run evals and get improvement report /skill-builder test --skill my-skill --verbose # Iterate: auto-refine prompt based on failures /skill-builder refine --skill my-skill

Development Loop

Define → Scaffold → Write Evals → Implement ↑ ↓ ←←←←←←←←← Refine ←←←←←← Run Evals ←←←←↓
🎯 Ship With Confidence

Run /skill-builder test --all in CI to catch regressions before merging. Treat eval failures like test failures.
